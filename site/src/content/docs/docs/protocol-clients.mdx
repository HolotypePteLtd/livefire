---
title: Write a WebSocket client
description: Connect to a room, send input, apply snapshots, and resume a session.
---

You need a WebSocket connection and a JSON parser to join a relay or physics room. The examples use protocol version 1, which the Livefire node uses for both built-in templates. A custom Dart authority can specify its own version.

## 1. Connect

Open a WebSocket to the room URL you got from the API (or your own
server):

```text
wss://host/play/<roomKey>?token=<oneTimeJoinToken>
```

The join token authorizes **one** WebSocket upgrade; the server
validates it before the upgrade and consumes it on success. Send your `join`
frame within **5 seconds** of connecting or the transport is closed
(`1008 Join timeout`).

## 2. Join / resume handshake

Send a text frame:

```json
{ "type": "join", "protocol": 1, "name": "Ada" }
```

- `protocol` — an integer that must **exactly** equal the room's configured
  protocol version, or you receive an error frame and close
  (`Incompatible game version`).
- `name` — 1-24 characters after trim; control characters and bidi overrides
  are rejected.
- Optional `resume` — a one-time resume token from a prior `welcome`
  (see step 6). Optional `binaryStates: true` — opts you into the binary
  state lane when the transport and codec support it (see step 5).

Refusals arrive as an `error` frame (with the reason) followed by close 1008:
banned identity, locked room, room at capacity, or template validation.

On success the server sends `welcome` on the reliable lane:

```json
{ "type": "welcome", "protocol": 1, "id": "p1", "resume": "…", "capacity": 8 }
```

plus any game-defined fields the template adds (relay: a sequence seed;
physics rooms: your assigned spawn). `id` is your peer id (`p1`, `p2`, …) and is
stable across resume.

Immediately after `welcome` you receive a **`baseline`** — the full
quantized state with its `epoch` and `tick` — and then a `snapshot` frame
with `initial: true` (seed any playback/interpolation clock from it).

## 3. Input and acks

Every non-handshake client frame whose `type` is not `join`, `ack`, `chat`,
`ping`, `moderate` or `leave` is a **game command**: the hub delivers it
verbatim to the room's authority. The frame shapes are template-defined —
relay rooms use `publish` / `publishRoom`, physics rooms use `input`
(see [room templates](/docs/templates/)).

Frame budget, enforced per peer:

- client-to-server frames are **JSON text** (UTF-8), capped at
  **4096 characters** — binary client frames are rejected;
- **120 packets/s** sustained (`Input rate exceeded` → error frame +
  close 1008), with a 600-packet buffer for a stalled host.

Acknowledge every snapshot you apply, either as a bare frame or piggybacked
on your next command:

```json
{ "type": "ack", "ack": 1204 }
```

`ack` is the latest applied snapshot tick. Acks outside
`ackTick <= ack <= sentTick` are ignored. If the server runs ahead of your
acks by half a simulation second you are considered blocked; with no ack
progress for **5 s** you are evicted (`1001 State receiver stalled`). A
client that cannot keep up receives at most one recovery snapshot per
simulation second — apply baselines when in doubt.

## 4. State replication

The server sends state as **baseline-relative deltas**:

- a full **`baseline`** on the reliable lane right after join/resume, then
  refreshed about **once per second** and on every **epoch** change;
- **`state`** deltas in between — `{ "type": "state", "base": <baseline
  tick>, "tick": …, "epoch": …, "delta": … }` — on the disposable state lane
  when the transport provides one;
- a `snapshot` frame (full state, no `delta`) accompanies each baseline
  refresh and recovery.

Delta rules that matter to a client implementation:

- A delta whose `base` or `epoch` does not match the baseline you hold is
  **discarded** — never buffered, never retried. Apply the next full baseline when it arrives.
- `delta` has the shape `{"remove": [keys], "set": {key: value-or-patch}}`:
  `set` replaces a key, and a `{ "patch": … }` value merges recursively into
  the existing object at that key.
- Floats are quantized to **4 decimal places** — do not compare replicated
  values for exact equality, and expect sub-quantum changes to drop out.

Discard the cached state when the epoch changes and wait for the new baseline.

## 5. Binary lane (optional)

If you sent `binaryStates: true` and the room is configured with a binary
`WireStateCodec` (FlatBuffers — bindings exist for many languages), states
arrive as binary frames instead of JSON. Binary frames **never begin with
`{`**, so a migrating client can detect the frame kind from the first byte.
JSON text always remains the fallback; clients that do not opt in keep
getting JSON.

## 6. Resume

Save the `resume` token in each `welcome`. To reconnect to a Livefire node, obtain a fresh room join token for the same identity, open the WebSocket, and send the saved resume token in the first frame.

```json
{ "type": "join", "protocol": 1, "name": "Ada", "resume": "…" }
```

Within the **15 s** grace window you get the same peer id back, a fresh
resume token, roster and chat replay. The token is single-use and bound to
your verified transport identity — a different identity gets
`Session identity changed; join again`. Resuming elsewhere closes the old
transport (`1000 Reconnected elsewhere`). After the grace window you need a
fresh join — and on a hosted server, a fresh join token.

## 7. Chat, roster and moderation

These ride the same reliable lane and work identically in every language:

- `chat` — 1-280 characters, single line; 4 messages / 10 s per player.
  Violations are a `socialNotice` frame to you only — no disconnect.
- `social` — the roster snapshot: members, leader, lock state, history.
- `ping` — `here`, `help`, `ball`; locations are **authority-supplied** and
  expire after 8 s.
- `moderate` — lock, kick, ban (host/leader only; bans bind to verified
  identities, never names).

## Close codes you should handle

| Code | Reason | Meaning |
| --- | --- | --- |
| 1000 | Reconnected elsewhere | your session resumed from a new transport |
| 1001 | Host closed the room | normal shutdown / drain |
| 1001 | State receiver stalled | you stopped acking for > 5 s |
| 1008 | Join timeout | no `join` frame within 5 s |
| 1008 | Removed by host | kick or ban |
| 1008 | Invalid request | protocol error (an `error` frame precedes it) |

See the [wire protocol reference](/docs/protocol/) for the full frame table and [room templates](/docs/templates/) for game-specific commands.
