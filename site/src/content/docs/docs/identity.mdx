Users can join with plain guest tokens (the server's API issues one-time
join tokens), or sign in with their Bluesky account. Below, "DID" means
the player's account ID on Bluesky's network. The two sign-in methods
compose; the quick shape:

| | Guest | AT Protocol sign-in |
| --- | --- | --- |
| Credential | one-time `jt_` token issued by the API | the same token, issued by the server after OAuth, carrying the verified DID |
| Bans | per-connection only | bind to the account ID (new handle, new device — still banned) |
| Resume | this device | the same account resumes anywhere; guests cannot resume a signed-in session |
| Profile | none | displayName/avatar prefetched from the user's PDS on the roster |

Sign-in is read-only by default: the server asks only for the `atproto`
(identity) scope. An optional repo-write grant exists behind the
`publishEvents` node setting (off by default) for publishing match
events as public records — per-event player consent required; see the
repository's shareable-rooms design notes.
