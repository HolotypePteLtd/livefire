A Livefire node runs rooms for one or more games. Your backend uses an API key to create a room and issue a one-time join token for each player. Give the client the room URL and its token. Keep the API key on your backend.

A guest room needs only the room SDK. AT Protocol sign-in and publishing are optional. See [where data goes during play, sign-in and publishing](/docs/how-it-works/#where-data-goes).

## Run the server

- [Run a room locally](/docs/multiplayer-server/) with the Dart counter example.
- [Host a server](/docs/self-hosting/) on a Linux machine with Docker Compose and Caddy.
- [Use the hosted preview](/docs/multiplayer-server/#hosted-preview) if you have a key for the hosted node.

## Choose a room type

| Room | What the client sends | What the server does |
| --- | --- | --- |
| [Shared state](/docs/shared-state-rooms/) | Values such as a ready flag or selected character | Checks ownership, size, and update frequency, then distributes the values. |
| [Physics](/docs/physics-rooms/) | Movement inputs such as direction and jump | Simulates movement against the configured colliders and sends positions to the players. |
| [Custom Dart room](/spec/room-authority.md) | Game-specific commands | Calls your `RoomAuthority` implementation to validate commands, update state, and produce snapshots. |

## Player accounts

Guests can join with a token from your backend. To show an account’s handle and avatar or apply a ban to its DID, [enable player sign-in](/docs/accounts/). If you run a Personal Data Server, see [Use an existing PDS](/docs/self-hosting/#already-run-a-pds).
